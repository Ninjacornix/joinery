# Joinery 0.6.0

Version: `0.6.0` · Godot base: `4.7.2-stable` · Sigstore-signed archives;
macOS ad-hoc signed and not notarized, Windows not Authenticode-signed.

Joinery now updates itself, and checks what it installs: every release archive
is signed in CI, and the updater installs only one it can verify. Agents spend
far fewer tokens and rounds on the same work: a stable prompt, a small project
map, short tool results, a precheck before submitting, batched Blender edits,
a Blender that stays running, an optional light model and reviews by risk, all
measured per change. Multi-step requests get a to-do with checks that say when
they are done, chats can be rewound or branched, and a quota stop hands the
request to another signed-in agent. Games record their play: replays become
tests, players can report bugs with the replay attached, old saves are checked
to keep loading, and console errors can be fixed on their own, each fix still a
change you review. New game features bring dialogue, enemy behaviour, cameras
and terrain; levels grow from your own example; puzzles are proven winnable;
characters can be reshaped by body region; Audacity is back; teams work
together over git; and Joinery has its own icon. Upgrading from 0.5.0 is as in
[0.2.0](0.2.0.md); from this release on, Joinery offers its own updates.
Changes since [0.5.0](0.5.0.md):

## Updates and signed releases

- **Check for Joinery updates…** in the Help menu, **Joinery: Check for
  updates…** under Tools, and a **Check for updates** link in the Project
  Manager (ADR 0083). All three run `joinery update`. It asks GitHub Releases
  at most once a day, works offline without errors, offers pre-releases only
  when you turn them on, and lets you dismiss a version.
- **Nothing is downloaded until you press Download and install.** The updater
  fetches only your platform's archive and checks its SHA-256 and its Sigstore
  signature: the certificate must name this repository's release workflow on
  that version's tag. A release without a signature is shown but not
  installed. Unpacking refuses absolute, `..` and linked paths.
- **The swap happens after Joinery exits.** The old install is kept under
  `updates/previous/<version>` (one is kept), the new one moves into place,
  each open project's `addons/joinery` is updated, and **Restart now** closes
  the editor the normal way, so unsaved scenes are asked about. **Go back to
  <version>** swaps back. A source checkout never asks GitHub on its own and
  never installs.
- **Release signing.** Every archive is signed keylessly with Sigstore from the
  release workflow, checked with `joinery verify` before publishing, and gets
  GitHub build provenance. macOS Developer ID signing with notarization and
  Windows Authenticode are wired in but run only once their accounts exist
  (`docs/signing.md`); this release has neither, and its notes on GitHub say
  so.

## Joinery's own icon

- A hand-drawn dovetail joint, brass on the dark theme's surface (ADR 0084),
  replaces Godot's icon on the editor and Project Manager windows, the macOS
  Dock, the boot splash and the Windows executable, and the Project Manager's
  wordmark leads with it. `Joinery.app`, the Windows folder and the Linux
  archive (a `.desktop` entry and hicolor icons) carry it too.
- The icon is three SVGs with a byte-for-byte raster build recorded in
  `release/icon/icons.lock.json`. The About dialog keeps Godot's credits, and
  games keep Godot's icon and splash: nothing in an exported game changes.

## What a change costs

- **Change metrics** (ADR 0054): every request records its agent turns, tool
  calls, checks, reviewer pass, review renders and send-backs, with tokens as
  each agent reports them, in a local file under `.joinery/metrics/`.
  `joinery metrics --project <path>` prints the breakdown (`--last N`,
  `--json`). Only labels, times and counts are kept, never prompts or replies,
  and nothing leaves your computer.
- **The Review tab shows what each decided change cost**: "2 min · 18k tokens ·
  1 round". Agents that don't report tokens show time and rounds only.
- `joinery metrics --rules` lists which checks send changes back most often,
  and `--errors` the console error counts (below).

## Fewer tokens and fewer rounds

- **A stable prompt** (ADR 0056): every agent's prompt starts with the same
  bytes turn after turn (Joinery's instructions, tools, the role's rules, the
  project), so each provider's prompt cache can reuse it. Claude Code no longer
  gets Joinery's instructions twice per turn, and each role is listed only the
  tools it may call; a reviewer carries about 85 to 90% fewer tool schemas.
- **A project map and a short scene** (ADR 0063): a ranked map of the project
  (scenes, scripts, autoloads, input actions, assets, recipes) of about 1.1k
  tokens goes with every turn (`joinery map --project <path>`), and the scene on
  screen is sent as a one-line-per-node outline instead of every property.
  `inspect_editor(node=…)` gives one node in full. Each turn also lists the
  files near the selection and the open scene (ADR 0080).
- **Short results, full output on request**: long tool results reach the agent
  as a summary that says what it left out, and the new read-only `details` tool
  pages through the rest. A script edit can send `patch` pairs instead of the
  whole file. Estimated on Joinery's own texts, a five-turn chat on a 60-node
  scene sends about 80% less input.
- **Forgiving patches** (ADR 0078): a patch whose text differs from the file
  only in trailing spaces, indentation or curly quotes still applies, and the
  result says which tolerance it needed.
- **Godot checks each script write**: a staged `.gd`, a scene with built-in
  scripts or a shader is checked at once in the offline worker, and only the
  errors that write added come back with its result. After three writes of one
  file in a row that add errors, the agent is told to stop and rethink.
- **`precheck`** (ADR 0058): the lead and workers can run the submit's checks
  on their change before submitting, without using a submit attempt or
  starting the reviewer. Every problem now comes with items an agent can act
  on: a rule, the file and node, what was measured, what is expected and a
  fix.
- **Accepted recipes as examples** (ADR 0064): `find_recipe` finds the
  project's own accepted recipes closest to a request ("a creaky gate sound"
  finds the door creak), so an agent starts from settled tool operations and
  numbers. No model is involved; `joinery skills --project <path> --find …`
  does the same.
- **A scope check before raw scripts run**: a raw Blender, Krita or
  SuperCollider script that opens sockets, starts programs, names files
  outside the change or builds code at run time is refused with a plain reason
  before the app starts.

## Faster Blender

- **`blender_batch`** (ADR 0057) sends several typed edits of one model (scale,
  pivot, decimate, material values, maps, bones, shape keys, cycles and action
  edits, up to 16) in one call and one Blender run, and records the same
  recipes as the calls one by one. Six edits took 4.6 s instead of 21.8 s, and
  the agent reads about a fifth of the text.
- **A warm Blender** (ADR 0062): each worker keeps one Blender running for
  typed operations and recipe fingerprints, restarted on any doubt. A single
  operation costs about a quarter of a second of Blender time once warm,
  instead of two Blender starts. `JOINERY_WARM_BLENDER=0` turns it off.
- **Review renders are kept by content**: a side that didn't change is never
  drawn again, so a second review of the same model opens at once.

## A light model and reviews by risk

- **`[agents] light_model`** in `joinery.toml` (ADR 0061), one name or one per
  agent, runs light work on a cheaper model: the reviewer's first pass on a
  low-risk change, the session summary, and the accessibility and performance
  agents' wording of a fix. A light pass never decides alone: whenever it
  objects, warns or is unsure, the main model reviews the same change and its
  notes are the ones you see. Unset, nothing changes.
- **`[agents] review = "always" | "risky" | "never"`**: with `"risky"`, a change
  Joinery's own checks judge completely (an existing texture recoloured within
  the palette, a sound's loudness, material values, a small scene edit) opens
  without the reviewer agent, and says why. Code, models, new scenes, the bible
  and brief, deletions and large changes are always reviewed.
- Both are set with `joinery reviewer --review … --light-model …` or in
  `joinery.toml`; Settings doesn't show them yet.

## Done when it is checked

- **A to-do for multi-step requests** (ADR 0060): the agent proposes the steps
  and what "done" means in terms Joinery can check: a place the playtest bot
  must reach, a minute of play with no errors, a test it writes, a check that
  must run, or something only you can judge. The to-do card lets you edit or
  remove lines and press **Go** (`[agents] todo_go`: `"multi"` by default,
  `"always"` or `"never"`).
- **Checked before you see it**: once the change passes Joinery's checks, a
  seeded playtest of the change checks every playing item. A Fail goes back to
  the agent once, then the change opens with its results: "2 of 3 done", each
  item with its evidence ("The bot reached Vault at 0:42, seed 4242.").
- **Steps that run together** (ADR 0072): with `[agents] run_steps =
  "together"`, steps that don't depend on each other are made at once as
  parallel tasks, each its own reviewed change ("Making steps 1 and 2 at
  once…"). The default still makes them one by one.
- **Runs that wait for idle**: with `[agents] unhurried = "idle"`, **Make it
  match**, the accessibility and performance fixes and the design check's
  agent pass wait until the editor has been quiet for a while inside your own
  hours (`idle_minutes`, `idle_hours`), on the light model when one is set.
  `/idle`, `/idle now`, `/idle clear` and `joinery idle`. No agent CLI offers
  batch pricing for agent turns, so Joinery doesn't use it.

## Project memory, commands and headless runs

- **`JOURNEYMAN.md`** (ADR 0077) at the project root holds standing rules and
  facts ("signals are snake_case", "the player is 1.8 m"). Every agent and every
  role reads it, up to 6,000 characters. `CLAUDE.md`, `AGENTS.md` and
  `GEMINI.md` stubs point at it where the project has none of its own.
- **`/remember <text>`**, or **Remember this** in a reply's right-click menu,
  adds a line as a reviewed change; `joinery memory add` does the same.
- **Project commands**: a `.joinery/commands/<name>.toml` file is a request with
  typed blanks, optional checks and sub-commands. They show under "This
  project" in the command menu: `/new-enemy Bat` goes straight to Journeyman,
  and a missing value opens a small form. `joinery command list|render|run`.
- **`joinery run --project <path> --request "…"`** runs one turn through the real
  chat host without the editor (`--json` for one event per line). It never
  accepts: the change waits in the Review tab, or for `joinery transactions
  accept|reject`.

## Rewind, branch, and another agent on a quota stop

- **Edit and resend** or **Branch** from any earlier request in the sidebar
  (ADR 0080; `joinery chats rewind`). Rewinding drops the later turns from the
  chat; Branch opens a new chat with the history up to there. Neither changes
  your files; undoing what the later turns changed is one optional reviewed
  change, and the Timeline keeps everything.
- **Summaries keep what matters word for word**: what each change became, the
  open to-do, open console errors and your answers.
- **A quota or usage-limit stop no longer loses the work.** The staged change
  waits and the sidebar offers **Continue with <agent>** for each other agent
  you are signed in to; the new agent starts from Joinery's own record of the
  chat and the staged files. `[agents] fallback_provider` switches without
  asking. Joinery never handles your sign-ins.

## Console errors, fixed when you ask

- **The Errors list** (ADR 0075): errors from the Output panel, the game's log,
  playtests and GUT failures, grouped so the same error printed every frame is
  one row with a count. Fix, Review, Try again and Ignore per row; Fix all when
  several wait. `[agents] ignore_errors` hides what you don't care about, and
  warnings are listed with `fix_warnings = true`.
- **Fix console errors automatically** (Settings → Project, or
  `joinery fix-errors`; `[agents] fix_errors = "ask" | "auto" | "off"`, `"ask"` by
  default). The offer for a new error gains **Always fix errors like this**.
  In `"auto"` the debugger and a worker make each fix in the background, one at
  a time with a pause between them by default, and the fix waits for your
  Accept like any change. Errors that came with a change still in review are
  never fixed on their own, and after two failed tries Joinery stops and says
  so.

## Replays and bug reports

- **Every Joinery game records its play** in debug builds (ADR 0059): every
  input on the physics frame it arrived, the seed, the start scene and a
  checkpoint of the game's state every second. `/record` in the sidebar records
  a play of the main scene, and `joinery playtest --record` records the bot's
  run.
- **Replays are tests.** `joinery replay add` keeps one in `tests/replays/`;
  `joinery replay run` replays them headless in stock Godot and says where a
  replay diverged. Once a project has any, every change that touches the game
  replays them, and one that now diverges or errors goes back to the agent
  with the frame and what differed (`[checks] replays`).
- **Report a bug** in the pause menu (F8) asks players "What went wrong?" and
  saves the note, the replay up to that moment and the last log lines on their
  own computer. Nothing is uploaded. `joinery reports list|open|import` reads
  them, and `/debug report <id>` has the debugger propose a fix.
- The puzzle-cards deal and the top-down camera shake now draw from the
  session's seed, so all seven starting points replay exactly.

## Saves that keep loading, and scene variants

- **Kept saves** (ADR 0066): the playtest bot saves through the game's own save
  system, and `joinery saves add` keeps a save as a test (`saves list`,
  `saves check`). Every change that touches saved state loads each kept save
  in the changed game; a save that no longer loads or loses data ("coin_3.
  collected is gone") goes back to the agent with the version numbers, and the
  fix is a migration step in `res://game/save_migrations.gd`.
- **Scene variants**: `/variant` makes a Godot inherited scene of the open
  scene, and `/variant <what differs>` asks the agent ("a red goblin", "the same
  crate, bigger"). A fix to the base then reaches every variant. The review
  lists only what a variant overrides, base value beside variant value, under a
  picture of both.

## Playtests and the running game

- **Coverage**: the playtest bot maps the level as it plays, heads for cells it
  hasn't reached, and the playtest card shows "Explored 34% of the level" on a
  map with the start ringed. `joinery playtest --reach "key room"` names places
  to head for first.
- **Heatmaps** (ADR 0067): deaths, stuck points and time spent per cell over the
  last five playtests (`[agents] heatmap_runs`), as toggles on the same map and
  in `joinery playtest --heatmap`.
- **The running game, judged**: `inspect_game` reads a game the agent started
  (scene tree, a node, the UI, a screenshot) for every role, and `drive_game`
  plays up to 64 timed inputs for the lead and workers, and for the
  playtester and debugger only where `[agents] game_input_roles` lists them.

## Accessibility

- **Longer text**: the accessibility check shows every screen again with
  Godot's pseudo-locale 30% longer and right-to-left marks, and lists every
  label or button that runs off the screen, is cut off or loses lines, with a
  screenshot outlining each. A cut-off one-line label gets a typed fix.
- **Findings by Xbox Accessibility Guideline**: the access card's "Xbox
  guidelines · 9 of 23 checked" lists each of the 23 guidelines as failing,
  passing, not measured or left to a person.

## Dialogue, enemy behaviour and cameras

- **Dialogue** (`joinery feature add dialogue`, ADR 0065): conversations in
  plain-text `.dlg` files with speakers, choices, conditions, variables and
  events, in a syntax close to Dialogue Manager's and Yarn's. The dialogue box
  follows the Accessibility settings and the screen reader, and the
  translations feature extracts its lines. A changed `.dlg` file plays through
  in the review, Before or After, with choices to click.
- **Enemy behaviour** (`behaviour`): behaviour trees as a few lines of text in a
  `.tres`, with ready guard, chaser, coward and wanderer trees and built-in
  sight, chase, flee, patrol and attack. Randomness follows the replay seed.
- **Cameras** (`camera`): 2D and 3D rigs that follow with a dead zone, look
  ahead, frame a group and shake, scaled by the player's screen shake setting
  and off with reduced motion.
- Each feature ships a `GUIDE.md` in the game that agents read before using it,
  and the playtest report includes what behaviour trees and dialogue were
  doing. All three are Joinery's own MIT GDScript; no add-on is installed.

## Terrain

- **`joinery feature add terrain`** (ADR 0068) for the 3D starting points:
  heightmap terrain with distance LODs, collision, up to four painted layers
  (the project's own textures, or colours by height and slope) and seeded
  scatter of the project's own models.
- Agents shape it with typed operations in `terrain_new` and `terrain_edit`:
  noise, raise, lower, flatten, smooth, erode, a path that eases the ground and
  paint. Each is a reviewed change with a recipe that bakes the same 16-bit
  heightmap byte for byte; a heightmap painted in Krita can be the base.
- Terrain3D, ProtonScatter and Spatial Gardener are listed as alternatives but
  not pinned or installed.

## Grown levels and winnable puzzles

- **Grow levels from your own example** (ADR 0069): `joinery blockout grow
  --sample <png|toml> --size WxH --seed N`, or `grow_level`, grows new blockout
  layouts from a picture you painted, a grid in text or one of your layouts,
  with Wave Function Collapse in Joinery's own code. Every grown level is
  checked so the spawn reaches each goal, the same seed grows the same level,
  and the review shows it beside your sample.
- **Puzzle checks**: grid puzzles in `design/puzzles/*.toml` (boxes, keys, doors,
  switches, gates, exits, move limits) are solved before review, with a rough
  difficulty; a level that can't be won goes back to the agent with the
  reason. Memory-card deals are checked against their move limit.
  `joinery puzzle check`.

## Characters by body region

- **Pick a body region** (ADR 0073): on the asset page and on the live model in
  review, a click on a character's body picks the region under the pointer
  (head, shoulders, arms, hands, legs and so on, read from its bones) and tints
  it; clothes are picked whole. "Bulkier shoulders" now has a target.
- **`set_body_shape`** changes an MPFB2 human's body settings and detail targets
  through MPFB2 itself and refits clothes and the rig where MPFB2 can.
- **`bake_shape_keys`** chooses which shape keys the game gets as morph targets
  (expressions, visemes); body-shape keys are baked into the mesh by default,
  and the `.blend` keeps them all. A new art bible rule,
  `[models.max_morph_targets]`, budgets them.

## More typed operations, and your own Geometry Nodes as kits

- **Krita layers** (`operate_layer`, ADR 0070): add, rename, reorder, hide,
  opacity, blend mode, merge, duplicate, delete, fill and filter layers, by
  name.
- **Material Maker values** (`list_graph`, `set_node_parameters`,
  `wrap_image`): change one node's parameters, checked against the node's own
  definition, or bring in a project image, without rewriting the whole graph.
- **One SVG element** (`edit_vector_element`): its attributes, style, transform
  or text, by id.
- **`joinery kits from-blend <file.blend> --group <name>`** turns your own
  Geometry Nodes group into a project kit: its inputs become the kit's
  parameters, a Seed input takes the kit's seed, and its materials follow the
  art bible's palette. Only Blender's own nodes are accepted. The `.blend` is
  recorded as your import.
- **Place a new model in the same change** (ADR 0055): a model made in this
  turn can be placed in the scene on screen before it is accepted, so a model
  and its placement reach you as one review. `instantiate_scene` can replace a
  placeholder and fit its size.

## Audacity

- **Audacity is a tool again** (ADR 0082), in its own offline worker, after the
  cause of its stalls was found. Agents edit an Audacity project with typed
  steps: import a recording, noise reduction from a noise profile in it,
  spectral edits, labels, track gain, pan and mute, and moving clips. The
  recipe rebuilds the project from your recordings, and the WAV, the label file
  and the `.aup3` replay byte for byte. Setup offers it again.
- **Speech-to-text is a Rule Zero stop.** The pinned Audacity MCP has
  transcription tools that run a speech model. Joinery never installs the
  model, the worker's build fails if one is present, and a call to any of those
  tools stops the turn for every agent. A catalog entry can now name such
  `generative_tools`.

## Tidy

- **`/tidy`**, **Unused content** in Settings or **Tidy** on the Review tab's
  Game checks row (ADR 0074) finds what the game never uses: files, input
  actions, autoloads, hidden or empty nodes and empty scripts, each with the
  evidence and what goes with it (imports, textures only it uses, recipes and
  `joinery.lock` entries). Files reached by a path built at run time are only
  "maybe used" and never removed with the rest.
- **Remove** makes one reviewed change; Discard or the Timeline bring it all
  back. `[tidy] keep` protects what you name. `joinery tidy --project <path>`
  prints the same; agents may read it, but only you can remove from the
  command line.
- **Free Joinery caches** clears old review renders, maps, tool results and
  playtest runs at once.

## Working together over git

- **`joinery team connect <remote>`** (ADR 0071) sets up a shared git remote with
  LFS, using your own git login; `team status`, `team clone`. Joinery stores no
  credentials, and any git host works.
- **Pull and Push in the Timeline**: teammates' entries carry their names, and
  a pull never touches changes waiting for review.
- **Art is never merged.** When you and a teammate both changed a model,
  painting or sound, your file stays and theirs waits in Review: **Use Ana's**
  or **Keep mine**, with pictures of both. Text that clashes waits the same
  way, and `joinery.lock` merges entry by entry.
- **Agents see teammates' work**: before an edit, the agent and you are told
  "Ana changed art/door.blend 10 min ago", and a file a teammate claimed
  (`joinery team claim --path … --hours N`) is not edited.
- **A teammate's change to the art bible or brief needs your approval** before
  it directs your agents.

## Share

- **Steam art** (`joinery share steam-art`, and the Share tab's **Steam art**
  group): header, small, main and vertical capsules, library capsule, hero and
  logo, composed in Krita from the game's own screenshots. The only text is
  the game's name; each image is checked for size, safe area, contrast and
  Steam's rules from `policy/steam_art.toml`. Nothing is uploaded.
- **Store media at 1920 × 1080**: screenshots and the trailer are now captured
  at Steam's minimum, so the library hero needs no soft enlargement. The
  itch.io cover is unchanged.

## Review and the asset page

- **A list of files beside the preview**: a change with several files shows one
  row per file with a thumbnail, its whole name and New, Changed or Removed,
  textures grouped under their model; Up and Down move through them. Narrow,
  the list folds above the preview. It replaces the filmstrip.
- Pictures sit in their own shape without dark bands, and the Before/After pill
  never covers them. A model's row shows its render framed on the model.
- **The asset page** puts the model preview first, with files, materials,
  objects, shape keys and bones in a compact grouped list beside or under it.
  A whole object can be tinted as well as a material.

## A first-project tour

- **Six steps** over the sidebar, picking, the message box, the review, the
  Timeline and Share (ADR 0072), once on a new project's first open; again from
  **Help › Joinery Tour**, **Project › Tools › Joinery: Tour** or `/tour`.
- **`docs/getting-started.md`** walks through a first game, from a starting
  point to sharing it.

## Fixed

- The shared policy hook answered Claude Code's tool check in a shape it
  rejects; denials and stops now use each event's documented shape.
- Blender operations refused an export named by its `res://` path ("Exports
  belong under art/ or audio/").
- A model whose texture was baked again exported a stray `_001` texture beside
  the original, and images nothing used; the new bake now takes the original's
  name and place.
- A Krita file with a filter layer fingerprinted differently on about half of
  its replays; its filter settings are now compared regardless of attribute
  order.
- Scrolling over the Mixer in a short panel moved faders instead of the view.
- In a narrow sidebar (340 px), long target chips widened the sidebar past its
  edge, and the reviewer's Model field, **Older versions**, the keep-fewer
  question, Run alongside, wrapped variants, command descriptions, sound kinds
  and match counts were cut or squeezed. All fit now.
- A model's row in review showed a plain grey square: the thumbnail cropped
  the ground in the middle of the render.

## Known issues

- **Signing**: the archives are Sigstore-signed and the updater verifies them,
  but the macOS app is only ad-hoc signed and not notarized, and the Windows
  build is not Authenticode-signed, so macOS Gatekeeper and Windows
  SmartScreen still warn on first launch.
- **Updater**: this is the first signed release, so a signed update has not yet
  been installed end to end. The Windows swap with locked files and the Linux
  check for running Joinery processes have not been tried on real installs.
- **Audacity**: the worker was tested only under amd64 emulation on an
  Apple-silicon Mac. Its mixdowns come out about 3.4 dB quieter than expected;
  the cause is not confirmed.
- New settings without a Settings row yet: `light_model`, `review`, `todo_go`,
  `run_steps` and `unhurried` are set in `joinery.toml` or on the command line.
- Not yet verified: exported games reading `.dlg` files and the terrain's kept
  PNGs, terrain bakes identical across CPU architectures, and `inspect_game`
  and `drive_game` against a real running game (tested with a stand-in).
  `JOURNEYMAN.md`, project commands, headless runs, steps together and the
  idle queue were tested with stand-in agents; no paid agent run yet.
- Token savings above are estimates from Joinery's own texts; `joinery
  metrics` will show the measured effect.
