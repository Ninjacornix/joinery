# Joinery 0.1 alpha 1

Version: `0.1.0a1` · Godot base: `4.7.2-stable` · Unsigned preview release.

This alpha connects natural-language requests to editable game projects and real
creative applications. The verified path includes Blender source creation and
editing, GLB export, Godot scene placement, review, rejection, acceptance and
clean recipe replay. Native supporting-tool fixtures cover painted Krita layers,
Inkscape vectors, Material Maker textures/materials, and audible SuperCollider
patches. See the [support matrix](../support-matrix.md) for capability and platform
limits and the [execution evidence](../../evals/results/alpha-tools.md) for tests.

## Before installing

- Install uv and make it available on PATH. Joinery uses Python 3.12 through uv;
  the first dependency setup may download Python and locked dependencies.
- Install and start Docker with Linux containers. Creative workers use
  `linux/amd64`, including emulation on Apple Silicon; first setup downloads
  substantial tool images. Leave several GB free and expect a slower first run.
  Run Joinery as a regular Linux user; worker UID:GID follows that account and
  root Linux invocations are refused.
- Install Git and Node.js/npm for the pinned MCP server installation. On Windows,
  install Git for Windows with Git Bash available for worker build scripts.
- Install Claude Code, Codex CLI, Gemini CLI or opencode and complete its own
  sign-in, or configure an API endpoint/model/key in **API / additional model**.
  A subscription alone does not install or authenticate its CLI. Codex is the
  provider exercised in the real end-to-end prop test; other providers have
  different live verification status in the support matrix.

Native Windows currently supports Codex's built-in read-only sandbox only.
Claude, Gemini and opencode sessions (including API profiles using opencode)
are explicitly refused on Windows because their equivalent read-only host
project boundary is not implemented. On macOS these providers require
`/usr/bin/sandbox-exec`; on Linux install bubblewrap (`bwrap`). Joinery refuses
to start them if that boundary is missing; it does not silently grant host writes.

The editor and launchers are unsigned alpha builds. macOS may require an
explicit Open/Privacy & Security approval; Windows may show SmartScreen. Check
the release's `.sha256` file and source before approving execution. A checksum
detects changed bytes; it is not a publisher signature or notarization.

Windows bundles include the matching DirectX runtime redistributables and their
original Microsoft license, code-license, redistributable list and README under
`joinery/licenses/`. These accompany the Godot license and copyright notices.
Codex CLI `0.167.0` is the version exercised by the native startup checks.

## Start a desktop bundle

Extract the archive for your OS and architecture. On macOS open `Joinery.app`;
on Windows run `joinery/Joinery.cmd`; on Linux run `joinery/Joinery`.
The first screen connects your agent, then advances to project creation/opening
after a usable connection is established. No agent account or API key is shipped
in the bundle.

Choose the project's tools, then run bootstrap from its bundled runtime folder
to prepare servers and creative workers. For macOS that folder is
`Joinery.app/Contents/Resources/joinery`; the Linux/Windows runtime folder is
`joinery`:

```sh
uv run --frozen joinery bootstrap --project /path/to/game
uv run --frozen joinery mcp status --project /path/to/game --probe
```

Check bootstrap's `unavailable` list and the actual MCP readiness output before
requesting work from a tool. Desktop **Open in** and successful provider login
do not by themselves prove a tool connection works.

## Start from source or a source/engine bundle

Run from the repository or extracted `joinery` runtime folder:

```sh
uv sync --frozen
# Source checkout only: builds the editor for the current host.
uv run --frozen python release/build_editor.py --jobs 4
uv run --frozen joinery launch
```

The native build needs the platform's normal Godot C++ build dependencies
(Xcode command-line tools on macOS, a C++ toolchain and development libraries on
Linux, or the supported Visual Studio C++ toolchain on Windows). The build script
syncs the pinned engine source if missing and refuses an existing dirty engine
checkout. A source/engine bundle already includes its matching binary, so skip
the build step there.

For a terminal-created project:

```sh
uv run --frozen joinery new /path/to/game --name "My Game" --tools godot,blender
uv run --frozen joinery bootstrap --project /path/to/game
uv run --frozen joinery launch --project /path/to/game
```

Use `joinery setup --project /path/to/game` for an existing project. Close its
editor before `update-addon`; Joinery keeps an addon backup and refuses hot
replacement in a running editor.

## What changed

- Separate Review workspace with media previews, scrollable change details and
  persistent Accept/Reject actions; wider chat, selected-target context and an
  upward slash-command menu.
- Native scene changes support undo/redo; saved files and creative documents use
  isolated transactions, conflict checks and interrupted-commit recovery.
- Native documents retain their owning source and refresh exports. Clean replay
  removes declared outputs in a disposable copy, so an unchanged old file cannot
  make a no-op recipe pass. Source preimages remain available for incremental
  edits.
- Existing Krita edits avoid unrecorded backup artifacts; Material Maker updates
  refresh existing exports and avoid claiming unrelated unchanged files;
  SuperCollider recipes recreate their native UTF-8 patch and audio output.
- Desktop packages include measured file manifests, engine/source notices and
  platform-specific launchers. Bundle verification extracts into a fresh path
  and exercises the shipped runtime.

## Exporting and checking releases

Editor packages and exported games are separate artifacts. The release smoke
script creates a disposable technical GLB scene and exports desktop games:

```sh
uv run --frozen python release/export_smoke.py --targets linux,windows,macos --output out/game-exports
```

It obtains the official
[Godot 4.7.2-stable export templates](https://github.com/godotengine/godot-builds/releases/tag/4.7.2-stable),
checks the pinned SHA-512 and template version, and uses their desktop runtime
templates. The editor is patched Joinery; these exported game runtimes are
upstream Godot 4.7.2 templates, not separately patched Joinery runtime builds.
Downloaded template cache defaults to `~/.cache/joinery/export-templates`; use
`--cache` to change it. The script writes `exports.json` with measured hashes,
then executes the current host's exported game to prove its GLB geometry loads.
`--smoke-only --output ...` runs that native check against existing exports.
Creating a foreign-platform executable does not prove it runs on that platform.
The Linux AMD64 export has additionally executed successfully in offline Docker
and reported `JOINERY_EXPORT_OK geometry=1`. Native Linux editor/bundle CI also
passes; the final three-platform exported-runtime release jobs remain pending.
macOS exported-game smoke ran on the local Mac.

Package and verify on the target host, using its actual editor binary:

```sh
uv run --frozen joinery package --desktop --output out/Joinery-alpha.zip
uv run --frozen python release/verify_bundle.py out/Joinery-alpha.zip
```

Optional `package --binary /path/to/editor --target macos-arm64` requires the
executable's measured architecture to match that target; it does not cross-build
another editor. `release/build_editor.py --github-env FILE` exports the built
binary paths for subsequent CI steps. The Linux native editor/bundle gate
passes; final macOS/Windows graphical/bundle and all three exported-runtime
release gates remain **pending**. See the desktop verification report for the
actual candidate and checks.

## Limits and recovery

Art direction is never automatically approved. Complete `art/bible.md`, type
`/art` and approve that exact version yourself. Accepting a draft or model preview
does not approve art direction; editing the bible invalidates its approval.
Technical test fixtures mock approval only inside isolated disposable tests.

Allow time for native tools and before/after review preparation: the measured
three-turn Codex fixture took about 36–68 seconds per model turn, plus 14–28
seconds for final review. Those are local single-run measurements, not latency
guarantees. Material Maker can emit shutdown warnings despite valid exports.
Optional application availability is not a claim of complete MCP automation.

Use `joinery diagnostics --project /path/to/game` for engine/addon/provider state
without credentials. File transaction recovery is available through
`joinery transactions list|recover|revert --project ...`; `revert` requires an
explicit `--id`. Save live editor changes normally; their undo history differs
from saved-file transaction recovery. Keep backups when evaluating an alpha.
