# Joinery 0.6.2

Changes since [0.6.1](0.6.1.md):

## A calmer editor

- **Scene tree and Inspector side by side.** The Scene tree sits above the
  Inspector in a column on the left, so you can pick a node and see its
  properties at once. Before, they were tabs in the bottom panel and only one
  showed at a time.
- **A shorter bottom panel.** It holds Review (always first), Files and Output,
  with its tabs above it. Timeline, Share and Mixer open from the rail as full
  pages, and every tab keeps the same height until you drag it.
- **2D, 3D and Script in the scene tab row,** plus Game while the game runs,
  with the screen you are on highlighted.
- **The 3D tools show from the start.** Select, Move, Rotate, Scale and Snap sit
  above the viewport; the rail button that hid them is gone.
- **Play is one button with a menu.** Play This Scene, Play a Scene… and Movie
  Maker are in the ▾ beside it, and Play no longer has the same colour as
  Accept, so during a review Accept is the one button that stands out.
- **A Joinery menu.** Joinery's commands, the tour and Check for Updates moved
  from Project › Tools to their own menu. The title bar shows the project's
  name only.
- **One Focus toggle.** ⤢ in the scene tab row hides the side columns and folds
  the bottom panel to its tabs; an open review stays open.
- **The rail is labelled.** The asset workspace is called Assets everywhere,
  dividers group the rail, and every item has a tooltip.

## Journeyman

- **Switching agent keeps your change in Review.** Switching agent or
  reconnecting no longer throws away the change waiting in Review. If
  Journeyman or its tasks are still working, Settings asks first.
- **Choose Opus, Sonnet or Haiku under Claude Code.** The reply options and
  Settings → Replies → Model list them, with the model Claude Code is set to as
  the default. Fast uses Haiku and Thorough uses Opus, and the picker shows the
  model ("Auto · Sonnet").
- **A failed connection offers the right fix.** The error banner says why and
  offers one action: Get or Update the agent, Sign in, Repair the project's
  policy hook, or Reconnect, with Switch agent always beside it and Copy
  details when the agent left error output. That output also goes to the
  Output panel, with keys and tokens removed.
- **Fewer surprises on the first message.** An out-of-date Claude Code or a
  missing Linux sandbox is reported when you connect, not when you send. If you
  moved or reinstalled Joinery, the project's policy hook follows by itself,
  and Joinery checks at connect that its own policy lets its own tools through.
- **Repair keeps your settings.** Repairing an agent's policy hook, and project
  setup, replace only Joinery's own entries in that agent's config; your other
  settings and hooks stay, and a config that isn't valid JSON is reported
  instead of overwritten.
- **A tidier sidebar.** Each card has one main action, with row actions shown
  on hover; card titles stand out from their rows; the agent's reply comes
  before the Accept and Discard buttons; a lost connection is said once;
  Settings lines up with the chat, says "Checking…" while it loads, and keeps
  its checks after the preferences; all cards share one style.

## Setup without a terminal

- **An out-of-date add-on says so, and updates itself.** Each project keeps its
  own copy of the Joinery add-on, and after a Joinery update that copy was left
  behind with nothing to say so. The sidebar now compares it with the one
  Joinery ships and shows "Joinery's add-on for this project is out of date"
  with **Update and restart**: the editor closes the usual way (asking about
  unsaved scenes), the add-on is updated with a backup, and the project opens
  again. If the update fails, the old add-on stays and the sidebar says why.
  When the chat refuses an older add-on, the same button shows instead of
  Reconnect and a command to type.
- **One notice, with a button that does it.** The line under the sidebar's top
  used to say things like "Godot isn't available yet. Rebuild its worker in
  /setup", named only the first app and asked you to type a command. It is now
  one plain notice that names every app with the same problem ("Blender and
  Krita need a refresh after the Joinery update.") and a real button:
  **Refresh tools**, **Start Docker**, **Check again** or **Open Project
  setup**. It sits below the Connect banner and waits while that is showing.
  The same words are used everywhere, and no screen talks about workers,
  images, bootstrap or MCP any more. **Rebuild** is now **Refresh tools**, so
  it no longer sounds like `/rebuild`, which rebuilds assets.
- **Refresh tools shows how it's going.** While a refresh runs the sidebar shows
  which step it is on, a progress bar, **Cancel** and **Show log**. The first
  refresh says it takes about an hour. If it fails, it says why in plain words
  (out of disk space, no internet, Docker stopped, out of memory, or the step's
  own error) instead of "#0 building with desktop-linux", and keeps the log a
  click away. A refresh started from the app rail, Project setup or a terminal
  shows its progress in the sidebar too.
- **One refresh at a time.** Pressing Refresh tools in the rail and in Project
  setup used to start two builds of the same images. The second now follows
  the first.
- **Only what changed is refreshed.** Each image is checked against what it is
  built from, so a change to one app's tools no longer marks every app out of
  date, a refresh rebuilds only the images that changed, and the shared base is
  rebuilt when its own sources change (it used to be built only once).
- **Start Docker checks again by itself.** After Start Docker, the sidebar, the
  app rail and Project setup ask Docker every few seconds for up to two minutes
  and carry on as soon as it runs.

## Fixed

- **A Docker hiccup looked like a missing app.** One slow or failed answer from
  Docker made an app read "not built" and offered an hour-long rebuild, and
  that answer was kept. Joinery now asks twice and double-checks before it
  says an app needs a refresh; if Docker can't say, the app shows as being
  checked and nothing is kept. Agents are told to ask you to press Refresh
  tools instead of being given a command with a placeholder in it.
- **`/doctor` said "That check couldn't finish" exactly when it found
  something.** It now lists each app with what to do about it.
