# Joinery 0.2.2

Version: `0.2.2` · Godot base: `4.7.2-stable` · Unsigned preview release.

A bug-fix release. Everything else is as in [0.2.1](0.2.1.md) and
[0.2.0](0.2.0.md), including installing, upgrading and the known limits.

## Fixed

- Creating a new project in a folder that already held a game overwrote it.
  The New project wizard only warned that the folder was not empty, then
  wrote a new `project.godot`, export presets, icon, `.gitignore`,
  `.gitattributes` and `.editorconfig` over the old ones and merged its
  starting point into the game. The wizard now needs an empty folder (a
  `.git` folder is fine). A folder with a `project.godot` says "This folder
  already has a Godot project. Open it from the project list, or pick an
  empty folder." Any other folder with files in it says "This folder isn't
  empty. Pick an empty folder for a new game, so nothing already in it gets
  overwritten." Create stays off in both cases (engine patch 0024,
  Joinery-only).
- `joinery game apply` no longer changes a game Joinery didn't make. When a
  folder has no Joinery game record yet and its `project.godot` starts
  another scene or is set up for C#, or it has C# or .NET project files, or
  scripts and scenes the starting point doesn't ship, it stops before
  writing anything and says what it found.
- The first time a starting point goes into a folder, Joinery copies the
  `project.godot`, `export_presets.cfg` and `joinery.toml` it is about to
  change to `.joinery/backup/<time>/` and says so. These copies are kept
  out of git.
- The Review tab said "Nothing waits for your review" while Journeyman was
  already telling you to accept: the change only appeared once its checks
  and before/after renders were done, up to a minute after the agent's last
  message. It now shows the moment the agent finishes, as "Preparing your
  review…" without Accept or Discard, and the list is read again whenever a
  turn ends or a change is decided. Agents now say a change will open for
  review instead of asking you to accept it before it exists.
- Preparing a review is faster: Godot's import check is skipped when nothing
  changed since the import after the last Blender or Krita export, the art
  bible's measured rules run beside it, and before and after render at once.
  Each part is timed separately in `.joinery/latency.jsonl`.
- A scene could be staged without the model or texture it loads, so
  accepting one change and discarding the other left a scene with a missing
  file. A review whose scenes point at files that neither the project nor
  the same change has is now refused, and so is one that deletes a file a
  scene still uses. Discarding or reverting a change says which scenes are
  left using a file only that change added.
- The asset workspace listed only assets already in the project. Assets in a
  change waiting for review are now listed and marked "Waiting for review",
  and models that scenes load from outside `art/` are listed too.
- An asset whose desktop app isn't on this computer said "Krita isn't
  installed … changing this model needs Krita" even when Krita is Ready for
  Journeyman, and called every asset a model. It now follows Joinery's
  readiness report ("Ask Journeyman to change this material") and names the
  material, texture or sound.

## Added

- Chats are saved per project and can be continued. The sidebar brings back
  your most recent chat when the editor opens; **Chats** in its header lists
  the others (rename them in place) and **New chat** starts over. Codex,
  Claude Code and agents with ACP session loading continue in their own
  session; otherwise the chat continues from a summary and says so. See
  [Saved chats](../editor-guide.md#saved-chats).
- Journeyman queues messages. While it works or a change waits for review,
  Enter adds the message to a queue at the end of the conversation instead of
  ignoring it. Each queued message keeps its targets and can be edited or
  removed; they go out one at a time when the reply finishes and nothing waits
  for review. After a failed or stopped reply the queue waits for **Send
  queued message**. Up to five messages can wait.
- A **Review** tab in the bottom bar lists every approval: changes waiting
  for you with Accept and Discard on each row (the badge counts them, as in
  **Review 2**), the art bible's approval, and accepted, discarded and
  reverted changes with Revert where it still works. Clicking the change on
  screen opens its full before/after review. `joinery transactions list` now
  also prints when each change was made and decided, which apps made it, its
  files and the art bible's approval state.
- **Share my view**: the eye button under Journeyman's message box sends a
  screenshot of the 3D or 2D viewport with your next message, and Journeyman
  can look by itself with the read-only `view_editor` tool, which also gives
  it the editor camera. Screenshots are references only: they are saved in
  `.joinery/attachments/` (kept out of git), never under `art/`.
- Images in Journeyman's chat: paste an image or image files, drop them on
  the message box, or choose them with the paperclip (PNG, JPEG, WebP; up to
  five per message, scaled to 2048 px). They show as thumbnails with **×** and
  go to the agent as images (Codex, Claude Code, and Gemini CLI or opencode
  when they accept images; otherwise as file paths). Like shared views, they
  are references, not assets.
- A context ring in Journeyman's header fills with how much of the model's
  context window the conversation holds (red from 90%). Hovering shows context
  used of the window, this session's input (with cached), output and the
  model. It uses what the agent reports (Codex, Claude Code, and ACP agents
  that send usage) and stays hidden when it reports nothing.
- Choose how many older versions a project keeps: **Keep older versions** in
  the New project wizard, and **Older versions** in Project apps and in
  Settings next to Compact. Last 50 changes up to 2 GB (the default), the
  last 10 up to 1 GB, only the newest, or your own numbers. A smaller choice
  says how many changes can no longer be reverted and how much it frees
  before it removes anything (`joinery history policy`, engine patch 0025,
  Joinery-only).
- A **Timeline** tab in the bottom bar shows how the project changed: each
  accepted change and each revert is one entry (what, who, how many files,
  when), with a filter and 50 entries at a time. An entry shows its files as
  coloured line changes, before and after pictures or sizes, with **Restore
  this file as it was** (a change you review first) and **Open file**. It is
  the project's own git history: new projects start it, existing ones offer
  **Start keeping a timeline**, and only each change's own files are
  committed, under your git name (`joinery timeline`, ADR 0034).

## Changed

- Joinery now owns each turn, for every agent. Journeyman hands its change
  over with `submit_for_review`; Joinery checks it then (art bible rules, Godot
  import, missing files, provenance, GUT tests where a project has them) and
  sends any problem back so the agent fixes it in the same turn. The review
  opens the moment the checks pass, with renders filling in after, instead of
  after the agent's last message. A change that never passes is dropped with a
  plain line from Joinery. Saved scenes are now always edited as staged files;
  only unsaved or new scenes change live. Near the context limit, the chat
  continues in a fresh session from a short summary (ADR 0035).

- The art bible the New project wizard drafts from your own answers now
  counts as approved, so art and audio work can start right away. The wizard
  says "Wrote the art bible from your answers. It counts as approved, so art
  and audio work can start. Fill in any open sections in /art; if it changes
  later, approve it again there."
  A later change to the bible still needs your one-click Approve in `/art`,
  skipped questions leave their sections open to fill in later, and
  Journeyman still cannot approve it (ADR 0033).
