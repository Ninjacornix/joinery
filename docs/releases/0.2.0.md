# Joinery 0.2.0

Version: `0.2.0` · Godot base: `4.7.2-stable` · Unsigned preview release.

New projects start from a small playable game, every project gets a game brief
and a fuller art bible, and accepted changes can be reverted from the sidebar. Read the
[0.1 alpha 1 notes](0.1.0-alpha.1.md) for installing, bundles and exports; that
part has not changed.

## What changed since 0.1 alpha 1

### New projects from a starting point

- `joinery new PATH --blueprint ID --features a,b` and the Project Manager's
  **New project** wizard make the same project. Six starting points:
  blank, first-person 3D, third-person 3D, 2D platformer, top-down arena and
  memory cards. Each one is a small game made of code and greybox shapes, with
  play tests, and no art or sound files ([ADR 0024](../adr/0024-blueprints-and-features.md)).
- Five features can be added at creation or later: controller support, save and
  load, online play, Steam and translations. `joinery blueprints` and
  `joinery features` list them.
- `/feature add|remove <id>` in the sidebar and `joinery feature add|remove`
  show a plan first (files, settings in plain words, notes). Nothing changes
  until you press **Apply**. The change can be reverted like any other.
- Steam: Joinery downloads one pinned GodotSteam release (4.23) into projects
  that have Steam on, checks its SHA-256 and records it in `joinery.lock`. It
  never publishes anything to Steam. Use `--steam-app-id` or add the ID later
  ([ADR 0027](../adr/0027-godotsteam.md)).
- The wizard has three steps: what you are making, features and apps, then the
  brief and art questions ([ADR 0029](../adr/0029-new-project-wizard.md)).
  Step 1 shows Name, Folder and the game in one sentence above the starting
  point cards.
- The Steam app ID field refuses numbers above 4294967295 with "Too big for a
  Steam app ID."
- The wizard refuses a Joinery home path that holds quotes, `$`, a backtick or
  `\` before it reaches the shell, for its background loading too.
- Projects made from a starting point open and run in stock Godot 4.7.

### Art bible v2 and the game brief

- The art bible has 20 sections from one schema. Required sections block
  approval; open ones are raised when the work reaches them
  ([ADR 0022](../adr/0022-art-bible-v2.md)).
- References are a board (`R1`, `R2`, …) with what to take and what to avoid.
  Reference files live in `art/reference/` and can be made before the bible is
  approved.
- Technical presets per starting point fill camera, budgets, animation, UI and
  accessibility numbers, marked as suggestions. A new bible takes the game's
  name as its title.
- Checked rules cover ten areas, among them loudness, triangle and bone budgets,
  scale, pivots, texel density, texture sizes and palette distance (CIEDE2000).
  A file that cannot be measured fails the check.
- `design/brief.md` says what the game is: pitch, loop, controls, platforms,
  online, saving, languages. It is drafted from the wizard answers and the
  starting point, and the controls table is read from the project's real input
  map ([ADR 0023](../adr/0023-game-brief.md)). `/brief` opens it.
- When the brief and the project disagree (the brief says online, online play
  is not added), the sidebar suggests the command. It never adds a feature
  itself.

### Sidebar, review panel and settings

- Each request is a card that shows sending, working (with a timer), waiting
  for review, accepted or rejected. Accepted changes offer **Revert** while their
  restore data exists, then say **Too old to revert**.
- A request that needs art waits at the art gate until you approve the bible,
  then goes out again.
- The Review panel sits in the bottom dock. The preview fills it; paths and
  recipes are behind **Details**. Accept and Discard stay on screen.
- Appearance: theme (match the editor, dark or light), accent colour (brass,
  blue, green or violet) and **Reduce motion**. Motion is short and only marks
  state changes.
- The settings page (••• in the sidebar) has reply mode, text size, reply
  times, appearance, project actions and history size with **Compact**.
- The app rail, asset workspace with audio player, and focus mode were rebuilt
  on shared components.
- Clicking a target chip above the message opens that asset in its tool.
- Classic Godot view: **Editor > Switch to classic Godot view**, the command
  palette or **Appearance > Layout** in settings switch between
  Joinery's layout and Godot's own docks, title bar and run bar. It applies
  after a restart, and each layout keeps its own docks
  ([ADR 0031](../adr/0031-classic-godot-view.md)).
- Scene tabs always show above the viewport, with **+** for a new scene.
- The run bar shows Play current scene, Play custom scene and Movie Maker next
  to **Play** again. Pause and Stop appear while the game runs.
- The app rail shows each tool's own logo (Godot, Krita, GIMP, Inkscape,
  Material Maker, Surge XT, SuperCollider), pinned with source and licence in
  [licenses/tool-logos.md](../../licenses/tool-logos.md). Blender keeps a
  drawn icon because its logo terms do not allow a cut-down version. The rail
  no longer goes blank in the light theme.
- Light theme contrast meets WCAG AA for text, borders, check boxes, radio
  buttons and scroll bars, checked by a test for both themes.
- New bibles and briefs carry a short "How to write in this file" note. The
  bible check and brief check suggest plainer words for filler such as
  "stunning" or "immersive"; this never blocks.

### Tools

- Removed as built-in tools: Aseprite, REAPER, MuseScore and Audacity
  ([ADR 0025](../adr/0025-tool-removals.md)). What to use instead:
  - Aseprite: Krita for pixel art.
  - REAPER: SuperCollider or Surge XT for sound design.
  - MuseScore: music written as MIDI and rendered through FluidSynth and
    Surge XT.
  - Audacity: typed sound edits (trim, fade, loudness, loop points, format) in
    Joinery's sound server. **Open in Audacity** still works when it is
    installed.
  - Any of them can still be added as your own custom tool.
- GIMP 3 edits `.xcf` files offline through Joinery's own adapter, and its
  recipes replay with `joinery rebuild`. The community gimp-mcp pin is gone.
- Surge XT 1.3.4 renders named parameters and notes to WAV offline.
- Blender: Rigify rigs export only deform bones; inspection lists rigs, shape
  keys and actions; textures are also written as PNG files under
  `art/textures/<model>/`; MPFB2 loads as a Blender extension.
- SuperCollider starts reliably in its worker.
- Recipes replay through each tool's own module.
- One readiness source: the CLI, setup, wizard, app rail and sidebar show the
  same state for each tool in the same words (Ready, Downloading…, Needs
  Docker, Needs your licence, Not available yet)
  ([ADR 0030](../adr/0030-one-readiness-source.md)).

### Part selection (first version)

- `joinery parts <model>` lists a model's objects, materials, texture maps,
  shape keys and bones, as Blender reports them
  ([ADR 0028](../adr/0028-part-selection.md)).
- In the Tools workspace, pick a part from the list or drag it onto the
  sidebar. In the 3D view, Alt+click picks the material under the pointer.
- Typed edits stay inside that part: one shader value, a map adjustment
  (invert, gamma, levels, contrast, tint, hue/saturation/value) or a height map
  baked to a normal map.

### History storage

- A change keeps copies of only the files it replaces, not the whole project.
  The working copy is a copy-on-write clone where the file system allows it
  ([ADR 0026](../adr/0026-change-history-storage.md)).
- `joinery.toml` `[history]` keeps the last 50 accepted changes or 2048 MB by
  default. The newest accepted change can always be reverted.
- `joinery history usage` and `joinery history compact`, also in settings.

### Licence

Joinery is now AGPL-3.0-or-later. Everything copied into a game (the editor
add-on, blueprints, features, templates, kits) and the engine patches stay MIT.
See [LICENSING.md](../../LICENSING.md). 0.1 alpha 1 remains available under MIT.

## Upgrading from 0.1 alpha 1

- Close the project's editor, then run
  `uv run joinery update-addon --project PATH`, or open it with
  `joinery launch --project PATH`, which updates and enables the addon.
- Bring an older art bible to the new format with
  `uv run joinery bible --project PATH --upgrade`. It only adds sections and
  markers, as a reviewed change. Approve the bible again with `/art`.
- A project that still lists Aseprite, REAPER, MuseScore or Audacity keeps
  opening. The id is skipped and a notice says what to use instead. To keep
  using one of them, add it under `[[tools.custom]]` in `joinery.toml`; its
  files are recorded as `origin: custom-tool`.
- Write a brief for an existing project with
  `uv run joinery brief --project PATH`.
- Change history from 0.1 still loads. Run `joinery history compact` once if
  you want to drop the old full-project copies; changes made before that can
  no longer be reverted.

## Known limits

- Live agent runs: the full request, tool, review and accept path with a real
  signed-in agent was run with Codex for 0.1 alpha 1. This release's new parts
  (starting points, features, brief, part selection, history) are covered by
  tests and real tool runs without a model, not by a new live agent session.
  Claude Code, Gemini CLI and opencode are still not verified live; on Windows
  only Codex is supported.
- Part selection is Blender only. On stock Godot, Alt+click works only while
  the model's root is selected; the parts list works everywhere.
- Starting points are greybox and silent. Real art and sound come from your
  tools after the bible is approved.
- A failed GodotSteam download still makes the project; Steam calls do nothing
  until the extension is installed. Steam follow-ups and the translations text
  scan run only after a feature change is accepted.
- Compact frees space by giving up older reverts. History sizes are file sizes,
  so a cloned file counts in full.
- GIMP: wrapping an existing PNG in a new `.xcf` does not yet record that PNG
  as a recipe input.
- Surge XT: no factory `.fxp` loading yet.
- Creative workers are Linux AMD64 and run emulated on Apple Silicon, so the
  first runs are slow.
- Switching between Joinery's layout and classic Godot applies after a
  restart; nothing switches live.
- Windows: the editor sometimes stops at startup with error 0xC0000409. It
  was seen twice in Windows CI, on the first launch of a fresh project in the
  light theme, and never on macOS or Linux. Starting it again works. A fix is
  planned for 0.2.1.
- Editor and bundles are unsigned.
